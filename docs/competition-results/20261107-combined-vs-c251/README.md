## 后续优化位置

三个计数查询已获得明显收益，带 LIMIT 的查询观测耗时增加约 **1.654%**，应继续检查其执行计划与相关度排序。现有构建日志表明倒排索引和文档词项索引的两个主要回填任务已同时运行，继续增加队列线程本身不能拆分这两个任务，不能据此预记进一步收益。

后续在同一候选程序和原样 20,000 行数据上读取了 7 个执行计划。原始计数查询的外层 `SUBPLAN SCAN` 不输出列，内部仍输出 `id`、保留相关度排序并执行回表；将内层投影写为常量的诊断查询消除了回表，但仍保留排序。三种有限结果计数均为 20，完整匹配数为 9,333。这是只读定位结果，尚未改变产品代码，也未测量新的优化收益。完整诊断归档 9 文件逐项核验，SHA-256 为 `7d0279a8df152c21009bc953083060cff134a6419335e2c70e4179a3ff62dcfb`。

39.633% 的对照基准是上述最高分代码在本机的运行结果。比赛满分门槛使用正式平台参考基线，两者不能直接换算；本地静态 CI 基线在旧版上已经达到报告上限，也不用于申报本轮正式成绩。

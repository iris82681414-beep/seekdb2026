## 适用条件与输出所有权

新 `JsonTextMemo` 为每个工作线程保留一个拥有自身内存的条目：二进制键至多 4 KiB，文本至多 16 KiB，另有长度元数据。键比较包含长度和全部原始二进制字节，没有哈希碰撞命中、固定输入或测试库名。打印模式沿用原有 JSON 线协议路径；该路径的日期打印不读取会话时区，数值、字符串及 opaque 打印也由二进制内容确定。

命中后仍调用既有复制辅助函数，将结果复制到当前单元格本地缓冲或请求分配器，避免后续列、行及请求覆盖线程缓存后破坏已生成的结果。未命中、超过任一容量、空值、无效数据及错误路径保留原有处理；仅在完整格式化与输出复制均成功后保存条目。没有修改 JSON 类型、SQL 求值、分词器参数校验或基准与评分文件。

## 采样依据与正确性

父版上针对原样 IK、BENG 输入的独立诊断，分别采集 100,000 次调用，按实际数据库 PID、主程序 DSO 和匹配的 Build ID 符号化。JSON 打印含子调用占所选 CPU 样本约 22.38% / 12.36%；配置规范化约 3%–4%，因此没有继续修改此前未取得收益的配置快捷路径。采样存在无法展开的调用帧，比例不是墙钟时间或可直接兑现的加速幅度。诊断调用次数不用于本轮性能比较。

候选通过 **17 组严格原生回归**。新增输入和父版真实生成的完整标准结果，附加在既有 `fts_index/tokenize_function` 用例内，原期望前缀保持不变。新增覆盖多行和多列重复值、NULL、数组、对象、嵌套、数字、Unicode、引号与控制字符、日期和 opaque 值、会话时区及 SQL mode 切换、字符集切换、事务回滚、预备语句及实际二进制协议，以及超过键或文本容量的结果。

另有 **8 个并发客户端、每版 800 条查询** 的独立比较，覆盖不同会话时区、重复及不同 JSON、多列覆盖和大值，两版输出逐字节一致。实际原样负载的调试诊断命中了新增复用分支，记录键长 **438**、文本长 **385**；该诊断的四类命中数仍为 8,001、11,000、7,332、20。首个探针因输入局部变量被编译器优化而无法完成读取，失败保留；后续探针只读取分支及正的容量内长度，不宣称直接观察到了优化掉的输入变量。调试运行的时间不纳入性能比较。

30 项产品输入冻结并与上述交付代码逐项一致。Linux 增量构建退出 0，用时 **17.37 秒**；嵌套 Unity 对象、编译日志、程序及恢复后的 **6,936** 个基线产品文件均已核验。该记录不是完整 master 构建或全仓测试。

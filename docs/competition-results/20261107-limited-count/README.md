## 适用条件与语义

优化识别仅有一个普通派生表的标量 `COUNT(*)`，外层没有过滤、其他聚合或其他结果消费者。内层为单表、自然语言全文匹配、普通 LIMIT 和 OFFSET，投影仅为列或字面常量，排序为空或仅按同一个 MATCH 分数排序。COUNT 只观察行数，行身份与这种排序不会改变结果，因此用原有投影清理工具创建常量投影，清除不影响行数的排序，LIMIT 和 OFFSET 表达式保持原样。

其他情况继续走现有路径，包括非空列计数、外层按文档字段过滤、其他聚合、分数阈值、布尔模式、分组、DISTINCT、赋值表达式、共享 CTE、FETCH WITH TIES 和返回实际文档。相关度用途检查只对无排序的常量输出放开 LIMIT 条件，WHERE 匹配判定沿用原有校验。通用全文检索改写开关保持原样。

修改为两个现有 C++ 实现及一项声明：`ob_transform_pre_process.cpp`、`ob_transform_utils.cpp`、`ob_transform_pre_process.h`。产品代码不含测试库名、查询词、固定 LIMIT 值或预设答案；基准 SQL、数据、计时和评分文件未修改。

## 正确性和实际执行路径

候选通过 **16 组严格原生回归**，包括此前 15 组和扩充的有限计数检查。新增输入和预期沿用既有 `score_usage_predicates` 套件，预期先在保留的直接父版上真实生成；原有预期前缀逐字节保留，候选使用同一份完整输入和预期进行比较。

新增覆盖零 LIMIT、多批次 OFFSET、超出匹配集的 OFFSET、空及 NULL 搜索文本、预备语句参数切换、显式扫描路径、事务删除及回滚、无主键表和分区表。1,031 行样本的匹配数为 825，OFFSET 820 后计数为 5；无主键和分区路径给出相同计数。需要观察行值的路径也已核对：独立排序样本的文档顺序为 3、2、4、1，带外层过滤的有限结果仍分别返回 1 和 0，混合聚合保留首条文档 ID 3；赋值表达式的状态变化与父版一致。

实际 20,000 行负载数据上的执行计划确认，原样 LIMIT 计数查询为 `is_index_back=false`、`calc_relevance=false`，相关度排序已消除；普通返回 ID 的有限查询仍为 `calc_relevance=true`，保留 MATCH 降序排序。三种诊断计数均为 20，完整匹配数为 9,333。计划和结果来自实际候选进程，运行文件摘要与回归使用的文件一致。

29 项编译输入逐一冻结。首轮因枚举作用域缺少类型限定而编译失败，源码已恢复；修正后完整构建退出 0，耗时 64.19 秒。第二轮仅复用首轮中已成功生成、输入摘要相同且有独立编译记录的对象，其余重新编译；完整失败记录与对象时间戳依据均已保留。
